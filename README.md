# Chat Memory RAG

SillyTavern UI 扩展，版本 0.1.4。支持 Content/Summary 内容索引、可选 MVU 消息快照、SHA-256 embedding 缓存、关键词与向量混合检索、可选 Rerank、独立 Text API 摘要生成以及 IndexedDB 导入导出。

## 安装与使用

在 SillyTavern 的「扩展 → 安装扩展」中填写 `https://github.com/robert4213/chat-memory-rag`，安装后刷新页面。更新时在扩展管理中检查更新。

也可将本目录复制到 SillyTavern 的 `public/scripts/extensions/third-party/chat-memory-rag/`（或酒馆当前用户扩展目录）。源码使用浏览器原生 ES modules，无需构建或 npm 安装。

1. 扩展设置中展开原生可折叠的「Chat Memory RAG」栏，点击「打开记忆管理」。折叠栏内也可直接开关扩展、查看索引状态和更新索引。
2. 在 API / Presets 的 Text、Embedding、Rerank 三张独立配置卡中填写地址、密钥、模型。Embedding 同时服务文档和查询，Rerank 可单独开启。Text 用于独立摘要生成。每卡支持拉取模型、测试当前表单、另存/加载预设。填写后保存设置即可；旧配置自动迁移，查询配置统一采用原文档 Embedding 设置。
3. 常规中启用；默认只索引助手正文。需要摘要时，选择 Summary 索引模式，在 Summary 页开启「使用独立 Text API 生成摘要」，设置摘要输入 include/exclude 标签与提示词。正文过滤后发送独立 /chat/completions 请求，提取摘要输出再 embedding。正常聊天请求不追加摘要提示词。
4. 内容提取设置 include/exclude，使用预览确认；缺失标签会 warning，不自动回退。
5. 按需开启 MVU，输入需要的变量路径。下一次正常聊天前读取前一层当前选中回复的消息变量。

Summary 模式下摘要缺失或为空：显示 warning，跳过该内容的 embedding。MVU 快照缺失、为空或字段过滤后为空：静默跳过 embedding，并移除对应旧 MVU 索引；仅 Debug 模式记录跳过事件。

摘要缓存使用过滤后的正文、摘要提示词、输出标签及 Text 模型配置的 hash。修改原文、规则或模型会重新生成。历史聊天首次建立摘要索引时，会为未缓存内容逐层调用 Text API；手动更新索引也遵循缓存。摘要不写回聊天正文。关闭额外摘要生成后，可以提取回复中已有的 summary 标签。

摘要的剧情时间由可见提示词要求模型提取，代码不强制补写任何时间字段。来源消息时间仅作为缓存元数据保存，不进入摘要文本、embedding 或注入。更新后自动排除旧版本带「来源消息时间（非剧情时间）」的索引；点击更新索引可用清理后的摘要缓存重新建立向量，或点击重新 Embedding 强制重跑最新摘要。

默认摘要提示词要求「剧情时间、地点、人物、事件、待续」五项分行输出，排除数值及系统初始化信息。完整 System 提示词显示在 Summary 页面并可完全编辑，不再隐藏追加规则；只有 {{summaryTag}} 会替换为所选输出标签。旧版本追加规则迁移一次为可见文本，后续可修改或删除。页面提供恢复默认提示词、经过 tag filter 的最终请求体预览（不发送请求、不含密钥）。
6. 点击更新索引，然后在检索预览检查结果。正常聊天时自动注入相关历史资料。

API 各用途独立配置；查询与文档须使用相同向量空间。浏览器直接请求 API，服务需要允许当前酒馆来源的跨域请求。密钥保存在本地 IndexedDB，导出时默认移除。所有数据属于当前浏览器与来源地址，换设备请导出/导入。

扩展在消息 extra 中写入自己的 cmrag_id 并保存聊天，用于中间删楼后的来源对齐；不修改消息正文或 MVU。删除、编辑、切换 swipe 后旧来源会排除。重新生成时限制检索到目标楼层之前。历史 swipe 的有效记录按当前选择重建，不保留独立历史版本浏览器。

## 设置与界面

魔棒菜单中的「打开 Chat Memory RAG」可直接打开管理面板，无需进入扩展设置。

聊天输入框旁的魔棒菜单提供「重新 Embedding 当前输入」。优先使用未发送的输入框文本，留空时取最近一条用户消息。它强制绕过缓存调用查询 Embedding，成功后更新检索预览，不发送消息或生成回复。失败时保留之前有效的向量。

启用 Summary 模式及独立摘要 API 时，此按钮会先强制重跑最新助手回复（当前 swipe）的摘要，再强制更新该摘要的文档 embedding，最后更新输入查询 embedding 与检索预览。保留标签过滤、剧情时间、来源时间和空摘要 warning；不批量重跑整段聊天。

概览、记忆、检索预览、常规、内容提取、Summary、MVU、API / Presets、检索与注入、数据管理、诊断和 TODO。额外人物事实解析保留在 TODO，没有解析请求。

## 验证与限制

### 请求超时与错误

每次 API 请求默认超时 300 秒（界面为 300000 毫秒，最大 300 秒）。旧连接设置与保存的预设会一次性迁移到此值，之后可自行调整。重试次数为 1 时最多发送两次请求，每次单独计时。

错误会明确显示调用用途（Text / Embedding 文档或查询 / Rerank）、模型、接口，以及超时、取消、HTTP 错误、JSON 解析错误或网络故障类别。非 2xx 返回以 api.http_error 记录状态、request ID 和响应正文，不要求开启 Debug；密钥脱敏，正文超过日志上限会标记截断。无响应的超时无法提供服务端响应正文。

### Debug 与日志

「诊断」页开启 Debug 模式并保存。普通模式在 IndexedDB 中保留 API 成功/失败、同步结果与警告。Debug 记录实际 API 请求体（含完整摘要提示词、过滤正文、embedding 输入和 rerank 文档）、响应（含文本、错误与接口返回用量）、调用 ID、服务商 request ID / generation ID、重试次数、耗时，以及本扩展最终安装的 RAG 注入全文。缓存命中不产生 API 请求日志，会记录 cache_hit。支持按级别筛选、刷新、清空与 JSON 导出，默认最多 300 条（可设 50–2000），并输出到浏览器控制台。

密钥、认证信息和请求头始终遮蔽；embedding 向量只记录维度。Debug 包含聊天正文与 MVU 输入，导出时也会包含；单段文本超过 128000 字符会显式标记截断。Debug 不记录酒馆完整主聊天 API 请求，只记录本扩展的独立 API 调用及本扩展安装的注入。OpenRouter 用量和 ID 以实际响应中存在的字段为准，无需接入后台账号。

运行 `npm test`、`npm run check`。本版本完成纯逻辑单元测试和语法检查，尚未在真实 SillyTavern 会话中联调。请先用测试聊天验证生成事件、swipe 与 MVU 版本兼容性。

v0.1 使用顺序 embedding 请求及内存余弦检索；未提供批量调度、变量树选择器、自动历史 MVU 回填、跨设备同步、EJS 模板渲染、角色事实抽取。历史内容可手动批量建立索引；MVU 在发送时及手动更新时只读取最新目标层。当前通过公开 getContext 和 Mvu 接口工作，Prompt Template / TavernHelper 状态在概览显示。初始化采用功能检测，尚不强制阻止缺少这两个扩展时的基本文本检索。

生成结束事件不能单独证明所有提供商都成功完成，停止生成会排除；网络失败的最终事件行为仍需真实酒馆验证。先核验此项再用于正式长聊天。
